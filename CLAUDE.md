## What this is

An ambient, voice-led listening experience that has become a **compositional tool**. Live at
https://project-drift.netlify.app/ (Netlify; **every push to `main` deploys**; `public/_redirects`).
You touch up to six *stops* on a valence × arousal colour field ("where I am" → "where I'd like to
be"), choose a length, press Begin: harmony generated by Eddy's voice-leading engine drifts through
the modes (and keys), one voice at a time, while the colours follow the same audio clock. You can
take the journey away as **MIDI** (a track per instrument, modes as markers), **WAV**, or a
**project file** that reopens it exactly.

Personal portfolio piece with the intent to grow into a standalone product; later, an Eddy
integration (the sibling app, `/Users/paulczech/note-threader`, a voice-leading tool for
songwriters — Drift is its *listener* side). No health claims, ever: a listening experience.
Competition (Endel, Calm) owns generative ambient; the differentiators are truly voice-led harmony,
the explicit A→B journey, restrained design, and now export.

**Defaults:** `/` = the mood field with the **pad** voice (lightest, 1.9 MB; first visit fetches
only that). `?ui=classic` = the original dropdown UI (still carries the Tao-style quotes —
**licence unchecked**, retire it). `?voice=pad|choir|choir-mixed|orchestra|pulse` overrides the
remembered voice. Remembered in localStorage: `drift.voice`, `drift.tempo`, `drift.bpm`, `drift.grid`, `drift.density`, `drift.variation`, `drift.root`.

## Stack

Vue 3 `<script setup>` + TypeScript, Vite, Tone.js 15 (dynamic import, own chunk), `@tonejs/midi`
(dynamic import, MIDI export), vue-multiselect (classic UI only). No backend, no router, no store
(state lives in `src/field/FieldApp.vue`). Planned: Ionic + Capacitor shell (see Open items).

## Code map

- `src/main.ts` — mounts `field/FieldApp.vue` (or `App.vue` for `?ui=classic`).
- `src/engine/` — framework-free, Tone-free, deterministic for a given seed:
  - `drift.ts` — `DriftEngine`: `LADDER` (lydian, major, mixolydian, dorian, minor, phrygian, locrian = parallel modes, adjacent rungs differ by one degree); `step()` one-voice moves via Eddy's `generateCandidates`; `shift(±1)` mode step; `modulate(±1)` key step (a perfect fifth, one pitch class a semitone, voices holding it follow); arousal sets voice count (3/4), register lean, openness; colour-tone/third/tonic bias.
  - `compose.ts` — `Variation` (still / gentle / flowing; `paceFor`, `variationAt`), `layoutTimeline(waypoints, walk, startTonic)` (stops → walks; **mode steps and key steps** share each walk, merged if closer than 2.5 s; `stateAt(layout, t)`), `Composer` (the pad's re-strike chains, `pull(until)` streaming, chunk-independent, `held` = whole sustained notes), `fifthsBetween`, `arousalAt`, `positionAt`.
  - `pulse.ts` — `PulseComposer` (ostinato; cell = one bar on a **grid** of 1/4, 1/8, 1/8T or 1/16, **density** auto/sparse/medium/full); `performer.ts` — `performerFor(voice, plan, rng, tempo)`; `voices.ts` — voice registry, `routeNote` (layers, edge fade, `byArousal` section balance, `loudnessKeep`), remembered voice/tempo/key; `moods.ts` — 21 words → valence/arousal, `rungFor`; `rng.ts` — `mulberry`.
  - `score.ts` — `scoreFor(voice, plan, seed, {bpm})` → DAW tracks/markers (pad re-strikes rebuilt into long notes, track per orchestra section, GM programs; pulse on its grid); `render.ts` — `renderDriftWav()` offline WAV; `eddy/` — copies of Eddy's `notes`, `scales`, `strategies`, `noteUtils`, `voiceLeading`.
- `src/field/` — the UI: `FieldApp.vue` (all state, plan building, readout, export wiring), `MoodField.vue` (dots, numbered stop markers, **stop bubble** for a stop's key/remove, pointer + keyboard), `JourneyRing.vue` + `lengths.ts` (1/4/7/10/∞), `SoundPicker.vue` (voices, tempo, BPM box, grid, notes density, change/variation, key), `ChoicePicker.vue` (a stop's grid/density/variation select), `ExportPicker.vue` (the **"file"** menu: MIDI, WAV, project, open project), `KeyPicker.vue`, `WordsFallback.vue` (accessible list incl. a key per stop), `FieldBackground.vue`, `moodPlane.ts` (positions, OKLab palettes, `inkFor`), `exportMidi.ts`, `project.ts`.
- `src/components/GenerativePlayer.vue` — renderless live player (samplers → low-pass → echo → reverb → master; queues events ~90 s ahead; emits progress; end fade ≤ 45 s). Other `components/`, `App.vue`, `data/` = classic UI only.
- `public/samples/` — `retro-pad` 1.9 MB, `analog-synth` 1.5 MB, `choir-female` 3.1, `choir-male` 4.1, `orchestra/<layer>` 10 MB (orchestra voice ≈ 17.8 MB incl. the choir sets). `scripts/render/` (offline renderer), `scripts/samples/orchestra.py` (rebuilds the orchestra layers).

## How it works (the decisions that shape the code)

- **Valence → mode** (brightness ladder), **arousal → density, dynamics, register, section balance, reverb** (not tempo). Each stop may also carry a **key**; the first stop's key is the journey's (auto = random each drift, or C…B; same setting in the sound menu and the first stop's bubble).
- **Transitions are voice leading**, never a crossfade: mode steps and key steps (fifths, shorter way round, ≤ 6) each change one pitch class by a semitone. Journey time: 15% settled, 55% travelling (a third of a leg settled at each middle stop), 30% arriving + fade to silence; ∞ = walk over 10 minutes then stay.
- **Voices:** `pad` (default), `choir`/`voices`, `orchestra` (8 sections; `byArousal` brings sections forward/back at constant loudness), `pulse` (an ostinato on Eddy's CC0 analog synth: a cell of 8 eighth-note steps, chord tones on strong steps, passing tones/rests on weak ones, notes substituted one at a time as the harmony moves, 4-cycle phrases, thinning at the end, dotted-eighth echo). **Grid and density are per stop** (the first stop's are the sound menu's, a later stop's are its own or "same" as the stop before, set in its bubble — pulse only; the **grid changes once, at the midpoint of the walk to that stop, on the next 4-bar phrase line** — the cell is always one bar, so bar lines don't move — keeping the beat notes and bringing the new steps in soft; **density eases along the walk**; a grid change is a `grid 1/16` marker in the MIDI). **Variation (every voice, per stop; the first stop's is the sound menu's `change` row, a later stop's its own or 'same'; eases along the walk): still / gentle / flowing. Gentle is the original behaviour, byte-identical.** It scales the time between harmonic moves (×1.6 / 1 / 0.6; the walk speed-up that lands mode/key steps is untouched) and, for the pulse, how many differing notes are substituted per cycle (still: only on phrase lines), how much a phrase varies (still: a breath in every other phrase; flowing: also in the 2nd cycle, and the arpeggio shape may change on a phrase line). Grid = steps per beat; density = share of steps sounding: sparse 50 %, medium 75 %, **full 100 % = every step, a continuous stream** (a step with no passing tone plays the tone's upper neighbour, then the tone), `auto` follows arousal and never fills the bar (62.5–75 %); no density at 1/4; the occasional 'breath' bar still drops a beat — it belongs to the coming variation control). **Pulse tempo is constant per journey** (default from the stops' mean arousal × slow/medium/fast, or a typed BPM 40–200). Pad/orchestra have no beat: MIDI is written at 60 BPM (a beat = a second).
- **Export:** MIDI via `scoreFor` (long held notes; first marker carries key | stops | BPM | voice | seed; a marker per mode/key change). WAV via `renderDriftWav` — **segmented** (90 s kept + 24 s lead-in, one shared seeded reverb room; a single long offline render is quadratic) and **only offered when nothing is playing** (`Tone.Offline` swaps Tone's global context). Project file `*.drift.json` (`drift: 3`; v1 opens as 1/8 + auto, v1/v2 as gentle): stops {valence, arousal, word, root, grid|null, density|null, variation|null} (null = same as before; the first stop's are the project's), minutes|"endless", key, root, voice, bpm|null, grid|null, density|null, seed, modes. Opening applies settings for this visit only (not the remembered ones) and its seed to the next Begin only.
- **Deterministic:** same plan + seed + tempo ⇒ same notes everywhere (live, MIDI, WAV; simultaneous events may be emitted in either order).
- **UI:** pointer events (mouse/touch/pen) + full keyboard (the field is one tab stop; arrows move between the 21 words; Enter toggles; Escape clears); words panel as the accessible fallback; per-region ink by WCAG contrast; menus are **always dark**; the sound menu stays open on a choice (× / Escape / outside tap closes); no mood text on the field (words only as quiet labels); no breathing, glows or box-shadows (Paul found them jarring); touch targets ≥ 44 px; axe-core 0 violations is the bar.

## Constraints and licences

- **The original Kontakt loops can never come back** (gone from the tree; still in git history — a history rewrite is a separate, deliberate decision, not done).
- New sounds need clear redistribution terms; audit before any commercial release. Paul's own recordings (retro pad; Yindad acoustic guitar) are safest. **Moog "Simple Saw" (pulse): CC0.** VSCO2 upright piano: redistribution allowed. **Sonatina Symphonic Orchestra (orchestra, choir): CC Sampling Plus 1.0** — credit required, no commercial redistribution of unmodified samples (ours are trimmed/level-matched/re-encoded) — **verify before any commercial release; add a credits screen** (credit strings are in `voices.ts`). **Pianobook samples (Eddy's felt piano, Mikor): not redistributable inside an app without the creator's permission** (from forum posts; unverified at the official page) — audition locally only. Ultra Ambient Pad is Julian Morgan's (Pianobook), not Paul's. General-MIDI/Magenta soundfonts: advised against for now (licence of hosted fonts unverified).
- Eddy's `analog-synth-temp` samples C#5…C6 are all copies of C5 (a bug in Eddy; Drift ships only E2–C5).
- Quotes in `EmotionConfig.ts` (classic UI) look like Tao Te Ching translations — licence unchecked.

## Verification recipes (what "verified" has meant here)

- **Type-check = `npm run build`** (`vue-tsc -b`). Plain `vue-tsc --noEmit` does **not** check the app.
- **Engine statistics:** throwaway TS bundled with esbuild and run in Node — keep the file in the project dir while bundling, delete after: `npx esbuild x.ts --bundle --platform=node --format=esm --outfile=x.mjs --banner:js="import {createRequire} from 'module';const require=createRequire(import.meta.url);"`. Typical suites: determinism, **chunk-independence** (pull in chunks vs once — compare order-insensitively), notes-in-mode statistics, arrival at the last stop's mode+key, one-semitone moves.
- **UI / audio in a real browser:** `npm run build`, `npx vite preview --port 4173`, drive headless Chromium with `playwright-core` (`npm i --no-save playwright-core axe-core`; a later plain `npm install` prunes them) using `--autoplay-policy=no-user-gesture-required`; check layout at 1280, 390 and 320 px, touch (`hasTouch`), downloads (`acceptDownloads`), axe-core with `runOnly: ['wcag2a','wcag2aa','best-practice']`. Don't kill the preview server while a test is using it; stale servers on 4173/4175 cause odd failures.
- **Offline renders for listening/measuring:** `node scripts/render/run.mjs timelines|journeys|export|pitch '<json>'` → `renders/*.wav` (gitignored; `export` runs the app's own WAV exporter; `"cut"` overrides segment/pre-roll for tests). Measure perceived share with A-weighted spectra and render solos *through the full voice*.
- **Round-trip checks:** read written MIDI back with `@tonejs/midi`; reopen a saved project and compare the readout (key, modes, BPM, seed) and the MIDI bytes.
- Headless cannot judge how it *sounds* or *feels*; never claim that. Real devices (iOS/Safari audio) still need Paul.

## Working style (same collaborator as Eddy)

**Role.** Claude is the senior architect, developer and music-technology partner — a full creative and technical collaborator, not just an executor. Authority to push back, flag problems before they become bugs, and make architectural calls. Paul has the final say, but Claude's judgment is actively valued: when asked "what do you think?", give a clear recommendation with reasoning, no hedging. Paul is the creative lead.

**Creative lens.**
- Think about the music as well as the code.
- Taoist, minimalist orientation: wu-wei, negative space, the beauty of what's left out. The best solution often removes friction rather than adding cleverness.
- What the app doesn't do matters as much as what it does. Complexity hidden, not eliminated.
- The listener should never have to think so hard they stop *listening*.
- Attend to where things are going, not novelty for its own sake. Community-minded; willing to try exotic solutions when conventional ones are merely adequate.

**How we work.**
- Direct and concise. Lead with the answer or the action; no padding, preamble or trailing summaries. Show or do instead of lecturing. Paul moves fast and dislikes talky, setup-heavy explanations.
- Discuss before implementing anything non-trivial, especially UI and copy: present options or a plan and wait for approval (an `AskUserQuestion` with previews works well for UI choices). Small fixes (typos, constants, one-liners) — just do them.
- Surgical edits over rewrites. Read and understand the code before suggesting changes.
- Mobile and desktop both matter (touch-first targets, keyboard and screen-reader access are requirements, not extras).

**Verification.**
- Use real diagnostic tooling proactively (see the recipes above). No blind fixes: reproduce a bug before fixing it; measure before and after.
- Confirm on a real device where it matters (iOS/Safari audio especially).
- Report honestly when something can't be reproduced, a fix didn't work, or something was only tested headless.

**Models and effort.** If a different model or effort level would suit a task better, say so — Paul switches it; Claude can't. (Normal-to-high effort suits the engine and UI work so far; reserve a higher level for large redesigns.)

**Git and builds.**
- Commit and push only when Paul asks. Clear prefixed messages (`feature:`, `fix:`, `revert:`, `chore:`) that read like short design notes, ending with the `Co-Authored-By` line the session specifies.
- If Paul says revert something, revert it and don't re-attempt it unprompted.
- Deploys are Netlify from the repo; every push to `main` deploys (branch for anything risky). Claude's part is the code and verifying builds.

**When to suggest a new chat (Claude: watch for these and tell Paul).** Paul wants the chats kept sharp. Say so plainly, and offer the handoff, when any of these is true:
- a feature or batch has just been **committed and pushed** and the next piece is a different area (the best moment — nothing is half-done);
- the conversation has been **compacted** (a context summary appeared) — especially a second time — or has become very long, with many large tool outputs, long test runs or repeated rebuilds;
- the work is about to **switch topic** (engine → UI shell, Drift → Eddy, a new app idea) or begin a **large refactor/redesign**;
- Claude notices its own recall slipping: re-asking settled questions, losing earlier details, or having to re-read files it already knows.
When suggesting it: first make sure this file is current and everything is committed (or say what isn't), then give a two-line handoff Paul can paste, e.g. "Pick up with grid and density for the pulse (CLAUDE.md → Open items #1)." Don't interrupt mid-task to suggest it — finish or reach a clean stopping point first.

**Context handoff.** Claude's memory doesn't carry between projects or sessions. This file is the source of truth — read it first in a new session, restate the plan for approval, then build. Put long measurements and dated reasoning in `docs/engineering-log.md`, not here.

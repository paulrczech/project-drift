## What this is

An ambient emotional listening experience. **Since 2026-10-16 (v1, on `main`): generative.** **Home page (2026-10-17): the mood field with the orchestra voice** — touch (or arrow-key, or pick from a words list) up to six stops on a valence × arousal colour field, choose a length on the ring, press Begin: an orchestral pad plays slow voice-led harmony that travels through the modes, its sections coming forward and back with the mood, while the gradient follows the same audio clock. URL options: `?ui=classic` (the original dropdown interface, kept for now) and `?voice=pad|choir|choir-mixed|orchestra` (default `orchestra`). Live at https://project-drift.netlify.app/ (Netlify, `public/_redirects`; **every push to `main` deploys**). History: v0 (2025) played two ~20s recorded Kontakt loops crossfading; those loops and their player were removed from the tree 2026-10-16 (still in git history before commit "remove the original loop engine").

Status: **personal portfolio piece, with the intent to grow into a standalone product** and, down the road, integrate with Eddy (the sibling app, `/Users/paulczech/note-threader` — a voice-leading tool for songwriters). Drift is the *listener* side of the same idea: Eddy lets a composer move voices by hand; Drift lets a listener move through feelings and the harmony follows.

## Stack

Vue 3 `<script setup>` + TypeScript, Vite, Tone.js 15 (dynamic-imported, own chunk), vue-multiselect. No backend, no router, no store (state lives in `App.vue`).

## Current code map

- `src/App.vue` — all state: `emotions` (any number, journey order), `position` (fractional index along them), `textIndex`; builds the plan (`planFor`: 1/5 held, 3/5 walking, then the last emotion forever), random tonic + seed per drift, keeps the player mounted through the 3s End-Drift fade (`audioActive`, `session` key).
- `src/components/GenerativePlayer.vue` — renderless: Tone Sampler (retro pad) → Reverb → master gain; queues `Composer` events ~90s ahead on the audio clock; emits `progress(position, textIndex)` every 250ms. See "Generative prototype — status" below.
- `src/components/EmotionSelector.vue` — multiselect (max 2), journey-length selector (two emotions only), start/end buttons.
- `src/components/BreathingBackground.vue` — idle gradient + one layer per emotion (layer 0 opaque, layer i fades in over i−1 as `position` passes i−1); inner layer runs the CSS "breathe" keyframes (transform/opacity only — see issue 10).
- `src/components/EmotionalSnippet.vue` — one `<p>` per emotion; `index` picks the visible one (6s crossfade).
- `src/data/EmotionConfig.ts` — 21 profiles: label, snippet. `src/data/EmotionGradient.ts` — 3-colour palettes.
- `src/engine/` — the generative engine (framework-free): `drift.ts`, `compose.ts`, `moods.ts`, `eddy/` (copies of Eddy's modules).
- `public/samples/retro-pad/*.mp3` — the only audio (Paul's own recording, 1.9MB).
- `scripts/render/` — offline WAV renderer (see "Rendering").

## Known issues & status

**Fixed (2026-10-16):** second emotion's background never showing; A/B order mismatch; three unsynchronized clocks (now one audio clock); 4s cycle; End Drift cutting the fade / throwing / starting audio after End (player stays mounted through the fade, `halted` guard, clamped gain read — verified with an analyser tap, 10 End timings, 0 errors); Chrome background flicker (issue 10, awaiting Paul's confirmation); dead code. **Gone with the loop engine:** thin variety/payload, 13-keys harmonic clash, loop seam, `?engine=loops`.

**Still open:**
- **Quote licensing:** snippets in `EmotionConfig.ts` look like Tao Te Ching translations — **check licensing before any public/commercial release**.
- **Contrast:** white snippet text on light palettes (e.g. happy's pale yellow) is weak. Needs a design discussion (text colour per palette vs. a subtle scrim).
- **Same-mode emotion pairs** (e.g. happy/cheerful) get a visual/text journey but little harmonic difference unless their arousal differs; tune `MOODS` by ear.
- **Issue 10, background flicker — fix applied, awaiting Paul's confirmation in Chrome.** Only Chrome; Paul's Loom screenshot showed rectangular tiles of the wrong colour plus bare white — unrasterized tiles. Cause: the `breathe` keyframes animated `background-position`, repainting three viewport-sized gradients (scaled to 4×) every frame. Chrome trace over a steady 4s window: **960 Paint / 11,146 RasterTask events → 0 / 0**. Fix: keyframes animate only `transform`/`opacity`, background-position static, `will-change` on the inner layers. The A/B bleed-through suspect is gone too (layer 0 is now opaque).

**Product questions Paul raised 2026-10-16 (after hearing the first renders — "they sound good") and where we landed:**
- *Journey length is user-set* — yes. `composeJourney` already takes seconds; presets 1/5/10/20 min plus a floor of ~20s. Short journeys need `beat` scaled to the length (a 30s walk of 5 flips can't wait 6s between moves).
- *Instrument/voicing selector* — yes, later. The composer is instrument-agnostic (note events), but each instrument needs its own articulation (the 5.5s re-articulation chain is pad-specific; plucked/piano need re-strikes or arpeggiation) and its own licence audit. Ship the pad first; add 1–2 more pad-like voices before any plucked ones.
- *Truly generative each time* — yes, already: the voice path is random per run (`Math.random`), seedable for shareable/reproducible runs. Honest limit: the mode, tonic (D), colour tone and register are fixed by the mood, so "happy" is always recognisably the same colour with a different path. More variety later from arousal (tempo/density/register), other roots, voicing choices.
- *Timeline / film-score use* — plausible and the architecture is the right shape: a journey is a list of keyframes `{time, mood}`; the ladder walk runs between consecutive keyframes, and arousal can be a second lane. Needs: planning backward so a mode is *reached* by the keyframe time, shorter beats for fast changes, and honest limits (2s attack/3s release smears hard cuts — fine for ambient underscore, not for hits on a cut). Offline WAV render already exists (`scripts/render`); MIDI export would come via Eddy's exporter. It's a different audience (editors/filmmakers: deterministic, editable, stems/MIDI, royalty-free from Paul's own samples) — park as a later product line, but **keep the composer's data model keyframe-shaped** so the two-point journey is just the simplest case. No UI until the listening experience is solid.

**To discuss at the appropriate time — dissonance control (Paul, 2026-10-16):** a darker starting emotion (e.g. Locrian) is likely dissonant; Paul wants a control that raises/lowers dissonance *within limits* so the mode's character survives and it stays listenable. **The mood-field interface (decided with Paul 2026-10-16; first run built behind `?ui=field`, uncommitted until Paul says so):** the screen *is* the control — a full-viewport field of valence (left → right) × arousal (bottom → top), coloured by blending the 21 palettes by distance in OKLab (`paletteAt`; exact at each word, continuous between). **Decisions:** (1) built for desktop *and* mobile — mouse, touch and pen all go through pointer events (tap, click or drag anywhere; hover previews on desktop); (2) accessibility is a requirement: keyboard throughout, screen-reader narration, reduced-motion; (3) **no mood text** — the Tao-style quotes are gone from this UI (which also retires the white-on-pale contrast issue and the quote-licensing question *for this UI*; the old UI still carries them), words survive only as quiet labels (on hover/focus/touch and on the chosen points) and as the fallback list; (4) the 21 dots are visible by default, fade as you settle (0.8 → 0.3 once a point is chosen → 0.1 while drifting) and return on touch/hover/focus; (5) continuous field, but anchored by the 21 named points (a touch within `SNAP` of a word lands on it; otherwise a free point, named "near X"); (6) journey length is a **ring** of 1/5/10/20/∞ around the Begin/End button, which also draws progress as an arc while drifting; (7) **length = the whole drift**: 15% settled at the start, 55% walking, 30% arriving, ending in a slow fade to silence (≤45s, ≤25% of the length) after which the interface rests on the destination colour; ∞ = walk over ten minutes then stay forever, no fade. Single emotion: stays that long, then fades (∞ = forever).

**Voices (built 2026-10-16, uncommitted):** `src/engine/voices.ts` is a small registry — samples + `register` (semitone lift of the engine's whole register) + `span` + optional absolute `ceiling` + optional `lowpass` + `level` + credit — chosen with `?voice=pad|choir|choir-mixed` (default `pad`; no picker yet; works in both UIs; the offline renderer takes `"voice":"…"`). Sources: SSO = Sonatina Symphonic Orchestra, `~/Music/Sampled Instruments/sso/Sonatina Symphonic Orchestra/Samples/…` (Paul found the male choir too harsh on its own). **Paul's feedback 2026-10-16:** the female choir is "beautiful but the high notes can be jarring". **Diagnosis (measured):** (1) at the first register ~8% of notes were pitched *up* past the highest sample (C6), which raises formants and sounds shrill; (2) C6 itself has 13% of its energy at 2–5 kHz vs <3% for the others; (3) the first level-match was by RMS, but the ear is most sensitive at 2–4 kHz, so A4/G#5/A5 sat ~3 dB louder than neighbours in A-weighted terms. **Fix:** samples re-converted level-matched by A-weighted loudness with a 3 dB/octave taper above C5 (G#5/A5 were cut 5–6 dB), 0.8s end fade; a hard `ceiling` of G5 (79) so nothing is ever pitched above its samples; a gentle low-pass (5 kHz / 4.5 kHz); levels matched to the pad by offline RMS (choir 0.30, mixed 0.26). **Two candidates to compare by ear** (renders 12 and 13 in `renders/`, pad reference 10): `choir` = female only (G4–C6), register +12, span 20 — 29% of notes get pitched *down* (mean ~5 semitones, worst 13), so the low end is warmer/more alto; `choir-mixed` = male G2–F#4 below G4 + female G4–C6 above (3.1MB + 4.1MB of MP3s in `public/samples/choir-female|choir-male`), register +8, span 26 — nothing is pitch-shifted at all (a bass-to-soprano spread). Spectral energy 2–6 kHz: 2.4% / 1.6% (pad ~0%). *Licence:* SSO is Creative Commons Sampling Plus 1.0 (see Eddy's CREDITS.md; Paul recalled "free for any purpose") — it allows sampling/transforming into new works but requires attribution and does **not** permit commercial redistribution of the unmodified samples; our files are trimmed/level-matched/re-encoded, but **verify before any commercial release** and add a credits screen (credit strings are in `voices.ts`). Not yet judged by ear.
**Orchestral pad (prototype built 2026-10-16, uncommitted; `?voice=orchestra`):** Paul's idea — "subtle and gentle brass, strings, woodwinds and choral sections", divided by note range. Paul's first listen: "Sounds like film music in a lot of ways" (liked it), but (1) he heard the **re-striking** (breathing pulse that takes attention) and (2) **only strings** across three journeys. **Model:** a `Voice` is a list of `Layer`s (each its own Sampler with a note range `min`–`max`, `gain`, optional `transpose`, edge `fade`, and a `chain`); `routeNote(voice, note)` (pure, tested) sends a note to every layer whose range holds it, softer toward the edges. Single-sample voices are one full-range layer. Voices also declare `attack`, `release`, `overlap`, `curve`, `link`/`links`, `maxHold`, which the composer takes (`plan.attack/link/links/overlap/maxHold`; defaults 2/5.5/attack/7.5 suit 8s pad samples). **Layers** (SSO `sus` sections; `scripts/samples/orchestra.py "<…/Samples>" [layer…]` rebuilds them — 112 kbps stereo MP3s, **10MB** in `public/samples/orchestra/<layer>/`, each 8s): basses (an octave *below*, notes 40–55), celli (40–64), violas (48–80), 1st violins (60–84), horns `sus-mp` (44–72), clarinets (48–80), flutes (58–84), choir (male+female, 46–79); engine register 0, span 28, **ceiling 81**, low-pass 6 kHz, `level` 0.19. **Fix for "only strings" (diagnosed by rendering each layer solo):** with my guessed gains the layers' shares of mix power were celli 41%, violas 22%, horns 22%, basses 6%, violins 4%, clarinets 3.7%, flutes 0.2%, choir 0.2% — the winds and choir were inaudible (and a soft horn blends into strings). Ranges widened (clarinets/flutes/choir now sound on 92%/60%/44% of notes vs ~80/26/21) and gains calibrated by measurement (`calibrate` loop: render solos, compare power shares to targets): now basses 3%, celli 17, violas 13, violins 15, horns 18, clarinets 13, flutes 9, choir 12 (strings ~48%, horns+winds+choir ~52%). Sampler velocity→gain is linear (measured). **Fix for the re-strike pulse (measured with the chord frozen, amplitude-envelope modulation in 0.15–1.2 Hz):** the old design swelled at the re-strike rate (18.7% at 0.38 Hz = 1/2.6s, 10 dB peak-to-peak) because every layer re-struck at the same instant and the old strike kept full level while the new faded in. Now each layer has its own re-strike *chain* (`NoteEvent.chain`, `Voice.links` 2.6–4.0s, jittered per chain) so swells do not line up, plus 2s linear fade in/out with 1.2s overlap: **pulse 6.4%, spread over rhythms, p-p 7 dB** (new crossfade alone barely helps: 16.5% — desynchronising is what works). Samples lengthened 6→8s (crossfade-looped steady middle; click score ≤ 2.6) so the longer holds fit. Chunk-independence fuzz incl. 8 chains: 1080 cases, 0 mismatches; no gaps in any held note; longest hold 6.2s. **Paul's second listen (2026-10-16): "Pulse is gone and sound much better"; hears brass and woodwinds but did not recall hearing any choir.** **Diagnosis:** measured by *perceived* (A-weighted) share the choir was 18% of the mix — but it sang the same notes as the violins and flutes, and in the vowel band (250–1600 Hz) it was only 14%: removing a layer that is 14% of a band changes the mix by <1 dB, so it was present but not identifiable (the horns, 25% of the vowel band, are what he hears). **Fix:** the orchestra's choir layer now spans male voices (G2–F#4) in the low-mid, where a sung vowel stands apart from the strings, plus female above G4 (range 46–79), and the whole mix was recalibrated by perceived share (target strings ~38%, horns 17, clarinets 10, flutes 9, choir 26; achieved basses 2, celli 8, violas 12, violins 13, horns 20, clarinets 10, flutes 9, choir 26; velocity cannot exceed 1, so the calibration scales others down and the master up). Measured effect of removing the choir: perceived −2.1 dB, and −3 to −5 dB at 500–1000 Hz (its formant signature) — previously <1 dB. Choir now sounds on 96% of notes. Level matched to the pad (RMS 0.107/0.099 vs 0.099; `level` 0.17). Renders 18 (anxious→serene) and 19 (nostalgic→joyful) in `renders/` (16/17 were superseded). **Orchestration that follows feeling (built 2026-10-16, uncommitted; Paul approved the idea: "I like this balance now and we should implement your idea about changing color over the journey"):** each orchestra layer has `byArousal: [dB at 0.1, at 0.5, at 0.9]` (straight lines between, flat beyond; 0 dB at the middle keeps the approved balance). `routeNote(voice, note, arousal)` applies it per strike (the player passes `arousalAt(layout, e.time)`, so the colour shifts smoothly along a journey as arousal does) and **holds the layers' combined power constant** (`loudnessKeep`), so moving sections forward does not change loudness. Gains carry 1/0.58 of headroom (all orchestra layer gains ×0.58, `level` ÷0.58 → 0.293) because the calm-end choir boost would otherwise need velocity 1.5 (clipped; found by the loudness test). Anchors (dB calm/mid/energetic): basses −2/0/+1.5, celli +1.5/0/−2, violas +0.5/0/−0.5, violins −2.5/0/+3, horns −3/0/+3, clarinets +1.5/0/−1.5, flutes −4/0/+4, choir +2.5/0/−3.5. **Measured** (perceived A-weighted share by section, each rendered solo through the *full* voice — an earlier solo measurement wrongly re-normalised the lone layer and cancelled the effect): calm: choir 46%, celli 15, clarinets 12, violas 11, horns 7, violins 5, flutes 3, basses 2 (voices+clarinets 57%, strings 33%, horns+flutes 10%); middle: choir 26, clarinets 19, horns 15, violas 12, violins 10, celli 9, flutes 8 (strings 32%, horns+flutes 23%); energetic: horns 33, violins 19, flutes 17, choir 10, violas 9, clarinets 7, celli 5 (horns+flutes 50%, strings 34%, voices 16%). **Multiple points (built 2026-10-16, uncommitted):** a journey is now an ordered list of **up to 6 stops** (`MAX_POINTS` in `FieldApp.vue`; the engine has no limit). **Interface:** each new tap/click/Enter appends a stop (a 7th replaces the last, announced); the dashed path is a polyline through **numbered markers** (1 = where you are, the last dashed = where you would like to be); tap a marker to remove that stop; Enter on a word that is the *last* stop removes it, on an earlier stop adds it again (a journey can return home); the words list grows one dropdown per stop plus a "then (optional)" slot (a revisit is just choosing the same word); hint "add another stop, or begin"; announcements "stop 3: hopeful…", "Drifting from sad through nostalgic, hopeful, joyful to serene for 1 minute." **Time:** the ring's length is the whole drift: 15% settled at stop 1, 30% arriving at the last (ending in the fade), and the 55% between split over the legs with a brief settle (a third of a leg) at each middle stop, so each mood is heard. **Change merging** (`layoutTimeline`, `MIN_FLIP_GAP` = 2.5s): the pad fades in/out over ~2s, so ladder steps closer than 2.5s blur; steps within 2.5s of the first of a group are made at that instant as one change of several semitone moves (still voice-led); opposite steps cancel (a quick excursion is skipped). ## Working style (same collaborator as Eddy)

**Role.** Claude is the senior architect, developer and music-technology partner — a full creative and technical collaborator, not just an executor. Authority to push back, flag problems before they become bugs, and make architectural calls. Paul has the final say, but Claude's judgment is actively valued: when asked "what do you think?", give a clear recommendation with reasoning, no hedging. Paul is the creative lead.

**Creative lens.**
- Think about the music as well as the code.
- Taoist, minimalist orientation: wu-wei, negative space, the beauty of what's left out. The best solution often removes friction rather than adding cleverness.
- What the app doesn't do matters as much as what it does. Complexity hidden, not eliminated.
- The listener should never have to think so hard they stop *listening*.
- Attend to where things are going, not novelty for its own sake. Community-minded; willing to try exotic solutions when conventional ones are merely adequate.

**How we work.**
- Direct and concise. Lead with the answer or the action; no padding, preamble or trailing summaries. Show or do instead of lecturing. Paul moves fast and dislikes talky, setup-heavy explanations.
- Discuss before implementing anything non-trivial, especially UI and copy: present options or a plan and wait for approval. Small fixes (typos, constants, one-liners) — just do them.
- Surgical edits over rewrites. Read and understand the code before suggesting changes.

**Verification.**
- Use real diagnostic tooling proactively: throwaway scripts for engine statistics, headless Chromium (playwright-core) for UI, screenshots. No blind fixes.
- Reproduce a bug before fixing it; measure before and after.
- Confirm on a real device where it matters (iOS/Safari audio especially) — desktop headless results aren't always the same, and headless can't judge how audio *sounds*.
- Report honestly when something can't be reproduced or a fix didn't work.

**Models and effort.** If a different model or effort level would suit a task better, say so — Paul switches it; Claude can't.

**Git and builds.**
- Commit and push only when Paul asks. Clear prefixed messages (`feature:`, `fix:`, `revert:`, `chore:`) that read like short design notes.
- If Paul says revert something, revert it and don't re-attempt it unprompted.
- Deploys are Netlify from the repo; Paul runs any release steps himself (on Eddy that means Xcode / App Store Connect / TestFlight). Claude's part is the code and verifying builds (`npm run build` runs `vue-tsc`).

**Context handoff.** Claude's memory doesn't carry between projects or sessions. This file is the source of truth — update it as decisions are made.
